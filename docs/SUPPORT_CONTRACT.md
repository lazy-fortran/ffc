# ffc Support Contract

This document is the public contract for the active `ffc` compiler path.
A program is supported only when every construct it uses appears in
"Supported now". Everything else is unsupported until the linked issue is
closed with executable tests.

The legacy conversion spellings `float()` and `dfloat()` are supported for
scalar integer arguments of kinds 1, 2, 4, and 8. They return default
`real(4)` and `real(8)`, respectively, and require exactly one argument;
contained procedures with the same name retain normal procedure shadowing.

## Architecture boundary

- FortFront owns lexing, parsing, AST storage, semantic analysis, type
  inference, diagnostics, and the compiler-facing frontend query APIs.
- `ffc` owns lowering from FortFront semantic data to LIRIC, the runtime
  ABI, diagnostics produced during lowering, object emission, executable
  emission, and behavioural tests for every claimed feature.
- LIRIC owns native code generation behind its session C API.
- New `ffc` compiler work uses LIRIC session C APIs through
  `iso_c_binding`.
- New `ffc` compiler work does not use LLVM bindings, MLIR bindings,
  HLFIR, or text-IR compiler paths.

## Architecture migration gates

The supported subset is being consolidated behind four contracts. New work
must use these contracts even when an older path still exists temporarily:

1. one FortFront binding identity across host, `ASSOCIATE`, `USE`, module, and
   submodule scopes;
2. one canonical descriptor for array storage, sections, dummies, pointers,
   allocatables, character arrays, and polymorphic views;
3. authoritative versioned `.fmod` records for imported callable and layout
   identity; and
4. one typed lowering engine for dispatch, array expressions, assignment,
   control flow, and I/O.

An implementation that reaches a construct through a text-name fallback,
legacy descriptor, guessed module layout, or parallel case handler is not a
new supported path. Such fallbacks must be removed with a behavioral oracle
when the corresponding migration issue closes. ABI or language-contract
changes also require matching updates to `RUNTIME_ABI.md`,
`ARRAY_DESCRIPTOR_ABI.md`, and the standard/FortFront contract that defines
the input semantics.

## Intrinsic allocatable owner contract

The direct LIRIC session supports standalone intrinsic integer, real (kind 4
and kind 8), and logical allocatable owners of rank one through rank three in
local and allocatable-dummy declarations. Runtime `allocate`/`deallocate`,
`allocated`, `size(a)` and `size(a, dim)`, column-major element read/write,
and dummy calls preserve the canonical descriptor and its three dimensions.
Whole-owner assignment between separate runtime-shaped owners of the same
supported kind reallocates the target and copies all elements. Scalar
broadcast remains limited to the existing descriptor cases where the static
extent is known. Rank four, derived allocatable components, aliases,
unsupported kinds, pointer/target owners, and unsupported whole-component
forms are explicit refusals.

## Intrinsic allocatable component contract

The direct LIRIC session supports rank-one and bounded rank-two allocatable
components of intrinsic integer, real, and logical type. Their component-owned
descriptors carry the data pointer and runtime extents; allocation,
`allocated`, `size` (with an optional dimension), column-major element
read/write, and deallocation are covered by the independent gfortran oracle.
Whole-component assignment, passing a rank-two component as an actual,
aliases, unsupported kinds, and rank greater than two are explicit refusals,
not partial support claims.

## Issue-422 polymorphic allocatable-array slice

A rank-1 `class(base_t), allocatable :: a(:)` array may be allocated with a
compatible concrete derived type-spec (`allocate(child_t :: a(n))`). The
allocation records the concrete dynamic type and its complete element stride,
so `select type (a)` can access both inherited and extension components of
each element. Incompatible type-specs and `SOURCE=`/`MOLD=` allocation of a
differing dynamic array type remain unsupported.

## FORALL evaluation contract

For fixed-size intrinsic array-element assignments, the direct session lowerer
copies the target's canonical element storage to stack memory before entering
the index loop. Every RHS and mask read resolves against that snapshot, while
the assignment address remains the original target. A block body is emitted as
one complete index nest per statement, so later statements observe all stores
from earlier statements. Reverse and ascending alias cases, plus a two-
statement ordering case, are covered by
test_session_forall_alias_compiler. Allocatable, runtime-shaped, character,
derived, and nonconforming-shape FORALL targets remain rejected or pending
their descriptor-specific contracts.

## Binding and module-boundary contract

Host association, `ASSOCIATE`, `USE`, module, and submodule references are
resolved by FortFront binding identity. The lowering context may retain a
Fortran spelling for diagnostics, but it must not synthesize storage or an
imported declaration from that spelling when the binding edge is absent. A
public module procedure whose call ABI is not yet supported is still recorded
in the versioned `.fmod` export set as non-callable metadata, so a separate
consumer can validate `use, only:` against the defining module. Attempting to
call that non-callable export remains a diagnostic; it must not silently bind
to a different procedure or be reported as an unknown module name. The
derived-dummy subroutine and function regressions in
`test_session_read_fmod_compiler` cover this boundary, with gfortran accepting
the function consumer as the independent positive oracle. Imported derived
types and host-polymorphic selectors remain unsupported until their public
FortFront binding facts and matching ffc behavioral tests land (see #584 and
FortFront #2974). FortFront's nested `ASSOCIATE` owner binding is corrected at
`d1c6a894`, with the direct-session regression covered by
`test_session_associate_selectors_compiler`.

## Supported now

### Unlimited-polymorphic assumed-shape arrays

`class(*), intent(in) :: values(:)` accepts a whole, nonallocatable,
nonpointer, nontarget explicit-shape array of default `integer` or `real(8)`.
`select type (items => values)` retains the canonical array descriptor view:
integer or real element type, 4- or 8-byte element size, column-major byte
stride, and the reserved runtime type-id word. Default/single-precision real,
logical, other kinds, sections, allocatable ownership, pointer/target ownership,
and global storage are refused with named diagnostics. The independent
gfortran differential oracle is
`test_session_class_star_assumed_shape_compiler`.

### Runtime-descriptor rank-2 allocatable copy

Direct LIRIC/session lowering supports `a = b` between separate local rank-2
intrinsic allocatables of default `integer`, `real`, or `logical` kind when
the source shape is available only in its runtime descriptor. The target is
reallocated to both source extents and copied with a bounded column-major
loop. The focused differential oracle checks allocation state, both extents,
values across two shape changes, and non-aliasing after source mutation.
Rank-1 runtime-descriptor copy behavior is preserved. Components, aliases,
global mutable state, unsupported kinds, and ranks above two remain cleanly
unsupported and retain their existing diagnostics.

Lazy mode also applies the Lazy Fortran dialect defaults (#438): a kind-less `real` is `real(8)`, and a dummy argument declared without an explicit `INTENT` is `INTENT(IN)`, so redefining it is a compile-time error. Both defaults are driven by the input mode recorded in the lowering context; a standard Fortran source keeps the processor default real kind and the language rule that only an explicit `INTENT(IN)` protects a dummy. |

A program-contained scalar function therefore resolves as contained both as a whole right-hand side and as an arithmetic or intrinsic-call operand, and its side effects execute exactly once. |
| Scalars | Scalar `integer`, `real`, and `logical` declarations and assignments. Compound declarations (`integer :: a, b, c`). Non-default integer kinds `integer(1)`/`(2)`/`(8)` (also named via `int8`/`int16`/`int64` and the `iso_c_binding` C-interop kind names, including `c_size_t`/`c_intptr_t`/`c_ptrdiff_t`/`c_intmax_t` and the `c_int_least*`/`c_int_fast*` family) support declaration, assignment, `+`/`-`/`*`/`/` arithmetic, comparison, and `print`. `real(8)` accepts the conventional double-precision kind alias names `dp` and `wp` in addition to `real64`/`c_double`/`8`. `complex`/`complex(8)` scalars support declaration, `+`/`-`/`*`/`/` arithmetic (including a mixed real/complex operand, which promotes the real side with a zero imaginary part), `cmplx()`, `real()`/`aimag()` component extraction, `conjg()`, `abs()` (the real magnitude via libm `hypot`), and `print`. The `%re`/`%im` complex-part designators read and write a scalar complex or a fixed-size complex array element (`x%re = 1`, `x(i)%im = 4`, and reads such as `x%re`/`x(i)%im`); `real()`/`aimag()` likewise accept a complex array element (`real(x(i))`, `aimag(x(i))`). `cmplx()` accepts a single value argument (imaginary part zero) and a trailing kind selector, whether keyword (`cmplx(x, y, kind=8)`) or positional (`cmplx(x, y, 8)`); the result kind follows the assignment target, so the selector is ignored. `dcmplx()`/`dconjg()` behave like the double-precision `cmplx()`/`conjg()`, and `real(z, kind)` extracts the real part with a trailing kind selector. A `cmplx()`/`dcmplx()` component argument may be an integer or a mismatched-precision real subexpression; it is widened (integer or single) or narrowed (double) to the target component precision. An integer or real scalar assigned directly to a complex variable becomes the real part with a zero imaginary part, and a complex-to-complex assignment across kinds (`complex(4) = complex(8)` and the reverse) converts both components. A single complex argument to `cmplx()`/`dcmplx()` (`cmplx(z, kind=8)`) is a kind conversion that carries both components. The double-precision kind aliases `dp` and `wp` resolve on `complex(dp)`/`complex(wp)` declarations, matching `real(dp)`. Scalar `parameter` named constants for `integer`, `real` (incl. `real(8)`/`real(dp)`), `logical`, and assumed-length `character(len=*)` with a compile-time literal initializer; the constant folds into uses in expressions, conditions, and `print`. Array, derived-type, and non-literal-expression parameters stay unsupported. The F2008 `TYPE(intrinsic-type-spec)` spelling (`type(integer)`, `type(real)`, `type(real(kind=4))`, `type(logical)`, `type(character(len=N))`, `type(complex)`, `type(double precision)`) names the intrinsic type itself and lowers exactly like the corresponding bare intrinsic declaration. A real literal's kind suffix naming another declared `integer, parameter` kind constant (`1.0_rk` where `integer, parameter :: rk = 8`) resolves that parameter's folded compile-time value instead of relying on a fixed alias list. Declaration-side `real(prec)`/`integer(prec)`/`complex(prec)` kind specs resolve the same way: any declared `integer, parameter` kind name (not just `dp`/`wp`) folds to its compile-time value and maps to the matching storage kind, on scalar declarations, `parameter` constants, derived-type components, dummy arguments, function results, and module variables. The old-style `parameter (name = expr)` statement declares a named constant: with no type declaration for the name it takes its implicit type (`I`-`N` integer, otherwise default real) and folds into later specification expressions such as array bounds. |
| Enums | Program-scope `enum, bind(c) ... end enum` blocks. Each `enumerator` binds an integer named constant of default kind: value is the explicit initializer (signed decimal literal), else the previous enumerator plus one, starting at zero. Multiple names per `enumerator` line and several enum blocks per program are supported; the constants fold into expressions, `print`, and `select case`. Module-scope enums and non-literal initializers stay unsupported. |
| Characters | Character literals, fixed-length `character(len=N)` variables, deferred-length `character(len=:), allocatable` with assignment, concatenation including self-aliasing and three-way concat, and compile-time `//` folding for character literal chains. A fixed-length target may also be assigned another character variable or a `trim`/`adjustl`/`adjustr`/`achar`/`char`/`repeat` result; the source is copied and blank-padded or truncated to the target's declared width, matching gfortran's fixed-length assignment. `==`, `/=`, `<`, `<=`, `>`, `>=` between character operands (variables, literals, `trim`/`adjustl`/`adjustr`/`achar`/`char`/`repeat` results, and `//` chains) use Fortran's blank-padded lexical ordering. `SELECT CASE` on a character selector accepts a lexical range label (`case ('a':'j')`) alongside literal labels. A character `parameter` named constant may declare a fixed length (`character(len=N), parameter`), which pads or truncates the folded initializer to N; its initializer may concatenate an earlier character named constant (`z = x // y`), not just literals. A local declared `character(len=len(other))`, where `other` is an already-declared character variable (a fixed-length or assumed-length dummy, for instance), takes its length from `other`'s runtime length at the point of declaration; assignment and further use behave like an ordinary local of that length. Other non-literal length expressions (a bare runtime variable, a call to a user function, or an intrinsic other than `len`) stay unsupported. The positional length form `character(N)` (including `character(*)` and `character(:)`, and the `character(N) function f()` prefix) is accepted as a spelling of `character(len=N)`. |
| Expressions | Integer and real literals, scalar variable references, integer and real arithmetic, integer comparisons (default `integer` and non-default `integer(1)`/`(2)`/`(8)`), scalar logical conditions. |
| Termination | Falling off `program main` returns zero. `stop <integer expression>` returns the integer expression as process status. |
| `if` | Integer comparison `if` blocks with terminating branches or branches that assign mergeable scalar values; scalar logical `if (flag)` conditions, including `.not.`/`.and.`/`.or.`/`.eqv.`/`.neqv.` trees, a logical array element (`if (flags(i))`), a derived-type logical component (`if (x%flag)`), `allocated(a)` on an allocatable array or deferred-length character, and a contained logical function's result. The one-line `if (cond) stmt` form without `then` works with any of these conditions. An `if` construct (block or one-line) whose then body is empty lowers as a condition-only branch: the condition is still evaluated and the branch merges with no body statements. A character relational comparison (`==`, `/=`, `<`, `<=`, `>`, `>=`, including the dotted `.eq.`/`.ne.`/etc. spellings) uses Fortran blank-padded lexical ordering; either operand may be a character variable, literal, `//` concatenation, `trim()`/`adjustl()`/`adjustr()`/`repeat()`/`achar()`/`char()` result, a character array element (`arr(i)`), or a character-returning contained function call (`label(i) == "one"`). Array-element writes inside `if` branches are recognised even when the FortFront semantic flag is missing. A relational comparison (`==`, `/=`, `<`, `<=`, `>`, `>=`) whose two operands are of clearly incompatible intrinsic type classes (numeric versus character, or logical versus either) is rejected with a "mismatched types" diagnostic when both operand types are statically obvious (a literal or a declared scalar); an operand whose type is not statically resolvable leaves the comparison to the normal lowering path. |
| `do` | Counted `do` loops with integer bounds and literal integer step (positive or negative), including nested loops in a contained procedure. Statements after a nested loop nest remain in source order and execute after the nest; `test_session_nested_do_tail_compiler` compares the emitted output byte-for-byte with a gfortran oracle. This contract requires FortFront `f3ab76ba` or newer, whose generic construct-span scanner handles the two-word `end do` terminator without absorbing following statements. |
| `goto` / labels | Simple `goto <label>` to a statement label in the same main program, including the arithmetic `if (e) l1, l2, l3` form that FortFront desugars to labelled `goto`s. A body that carries any statement label is lowered label-aware: each labelled statement starts a basic block, a `goto` branches to it, and every scalar integer/logical local is held in a stack slot so its value survives arbitrary branch edges (the backend rebuilds SSA). Computed `goto (l1, l2), e` selects the 1-based label named by `e`; a selector outside the label-list bounds falls through to the next statement. Branches across a contained procedure boundary remain outside this contract. |
| `pause` | `pause` and `pause <message>` write the gfortran-compatible banner and resume prompt to stderr, then wait for stdin. End-of-file terminates with status zero after flushing earlier output; statements after the `pause` do not run. |
| `select case` | Single-arm or multi-arm `SELECT CASE` with literal integer labels, integer or character ranges (`case (1:5)`, `case ('a':'j')`), character labels, multi-label arms (`case (1, 5)`), and `case default`. Arms may terminate (`stop`/`return`) or fall through to a merge after the construct; non-terminated arms carry mergeable scalar values via an N-way PHI. An integer `SELECT CASE` whose CASE labels overlap is rejected with a diagnostic when the overlapping bounds are integer literals (single values, closed ranges, and open-ended ranges are compared; non-constant labels are skipped). |
| `select rank` | Static-rank selectors retain the existing inline dispatch: the matching `rank (n)` arm is lowered, otherwise `rank default`. A narrow genuine assumed-rank slice is also supported for one contained subroutine with one scalar-element `REAL` dummy declared `x(..)`, a rank-1, rank-2, rank-3, or rank-4 whole-array actual, and exactly one matching `rank (1)`, `rank (2)`, `rank (3)`, or `rank (4)` arm. The caller passes the canonical 200-byte `array_descriptor_t`; the arm binds its base pointer and runtime extents, and rank-1 uses its descriptor byte stride while rank-2, rank-3, and rank-4 use column-major element addressing from the descriptor extents. `rank default`, `rank (*)`, scalar actuals, ranks other than one through four, dynamic shapes, sections/aliases (including pointers), non-REAL elements, multiple or missing rank arms, ownership, and global-state cases are refused with named diagnostics. Whole-array reductions and other dynamic-shape operations remain outside this slice. |
| `where` | Single-statement `where (mask) a = expr` and the construct form with a final unmasked `elsewhere`, over fixed-size rank-1 integer, `real` (kind 4), and `real(8)` arrays. The mask is a scalar comparison whose operands are conforming array elements or broadcast scalars (`a > 0`, `b == 0`); integer masks use `==`, `/=`, `<`, `<=`, `>`, `>=`, real masks use `<`, `<=`, `>`, `>=`. Each body assignment lowers per element: the mask element selects between the body value and the current element (the `elsewhere` body selects the complement). Body right-hand sides accept whole-array `+`, `-`, `*`, scalar broadcast, and the elemental real intrinsics that lower to libm (`sqrt`, `exp`, `log`, `sin`, `cos`, `tan`, `abs`). Masked `elsewhere`, nested `where`, and array-section operands are rejected with a diagnostic. |
| `forall` | Single-statement `forall (i = lo:hi[:stride]) a(i) = expr` and the block form `forall (...) ... end forall`, over integer loop indices. Each index lowers to a counted loop; the indices form a sequential loop nest, so a multi-index `forall (i = ..., j = ...)` and a `forall` body that itself contains a `forall` both lower as nested loops. An optional trailing mask (`forall (i = lo:hi, i > 2) ...`) guards the body with a conditional branch; the mask is a scalar comparison over the loop indices and broadcast scalars. Body assignments write rank-1 or rank-2 array elements directly to memory. Masks whose operands are array elements (`a(i) > 0`) are rejected with a diagnostic. |
| `associate` | `associate (name => expr)` over scalar integer, real, or logical selectors, with one or several associations in one construct (`associate (u => a, v => b)`). Each name binds to the selector value for the construct body; the binding is dropped at `end associate`. The body may read the name in expressions, `print`, `stop`, and assignments. A rank-1 unit-stride array-section selector (`associate (x => a(lo:hi))`, source element kind integer, real(4), or real(8)) binds the name to a view onto the section's own storage, reindexed to lower bound 1: `size(x)`, element read, and element write all flow through to `a`. A scalar derived-type component selector (`associate (s => a%comp)`, component kind integer, real, or logical) binds the name to the component's own storage address: reads and writes through `s` flow to `a%comp`. Non-unit-stride and rank-2 array-section selectors, array-expression selectors (`z => x + y`), and character selectors are not yet supported. |
| Procedures | Contained integer, real, and logical functions and subroutines, including early `return` inside each. A function whose result type is left to Fortran implicit typing (no explicit result type on the header and no body declaration of the result variable) takes the default letter-rule kind: a result name beginning `i` through `n` is integer, otherwise real. An in-scope `implicit` statement that overrides the default is not honoured for the result kind. `stop` inside a contained procedure terminates the program via libc `exit`. Scalar procedure actual arguments use pointer parameters with copy-back for variable actuals. `optional` integer dummies are supported with `present(arg)`: an omitted actual is passed as a null pointer (the caller pads to the callee's parameter count) and `present` is a null check. `if (...)` without an `else` and `.not.` in a condition are supported. A `character(len=*), intent(in)` dummy receives a character actual (deferred-length variable or literal) through a {data pointer, length} descriptor, so `len`/`len_trim` see the actual length. A fixed-length `character(len=N), intent(in)` dummy uses the same descriptor but keeps its own declared width N rather than the caller's runtime length, so it sees exactly the first N bytes of a longer actual. A `character(len=:), allocatable, intent(out)` dummy receives the address of the actual variable's own descriptor, so an assignment inside the callee writes the new data and length back to the caller. A scalar actual (a scalar literal or an identifier bound to a non-array symbol) passed where the callee declares an array dummy is rejected with a `Rank mismatch in argument` diagnostic (F2018 15.5.2.4); the callee must be a procedure defined or interfaced in the same unit (an external call without an explicit interface is left alone); a nonallocatable actual with statically fewer available elements than an explicit-shape dummy (whole array, array element, array section, array constructor, or `reshape`) is rejected with `Actual argument contains too few elements`. A call passing more actual arguments than that same in-unit callee declares dummies is rejected with a `More actual than formal arguments` diagnostic; fewer actuals than dummies is left to the optional-padding path (a trailing omitted optional dummy stays valid), and a type-bound call carrying a hidden receiver is not count-checked. A contained procedure may reference a host-associated named constant (an `integer, parameter` of the containing program or module) in an integer expression; the value folds from the declaration FortFront's binding resolution names at the reference, so an identically spelled constant in a module the unit does not `use` stays invisible and keeps the undeclared-name diagnostic. Host-associated intrinsic scalar variables use binding-keyed global storage shared with the host; their declared type from the declaration registry is authoritative even when use-site inference inside an internal function reports a different implicit type. Reads and writes in the contained procedure are therefore visible in the host. Actual arguments may be written as keyword actuals (`call sub(b=2, a=1)`, `r = f(hi=3, lo=1)`): positional actuals fill the leading dummy slots and each keyword actual binds to the dummy its name selects, taken from the callee's definition or interface in this unit or from the dummy names a separately compiled module procedure records in its `.fmod`. A dummy no actual reaches is passed as an absent optional (null pointer). A keyword naming no dummy of the callee, a dummy supplied more than once (by two keywords or by a positional and a keyword), and a positional actual written after a keyword actual are each rejected with a diagnostic; a keyword call to a callee with no visible signature, and keyword actuals in a type-bound call, stay unsupported. |
| Intrinsics | **Numeric:** scalar `abs`, `iabs`, `min`, `max`, `mod`, `modulo`, `sign`, `dim` for integers; `abs`, `min`, `max` for reals; `real()` (integer-to-f32; a BOZ-literal-constant argument reinterprets its bit pattern as the result kind's representation, per F2008 13.7.128, instead of converting the magnitude), `dble()` (any-to-f64, same BOZ bit-reinterpretation), `int()` (truncate toward zero), `nint()` (round half away), `floor()`, `ceiling()` as integer results. These lower inline with LIRIC scalar ops and PHI merges. **Math:** real transcendentals `sqrt`, `exp`, `log`, `log10`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`, `erf`, `erfc`, `gamma` (`tgamma`), `log_gamma` (`lgamma`), and `hypot` lower to the matching libm call on `real(8)` operands; integer actuals promote to real first. `aint` (truncate toward zero) and `anint` (round half away from zero) lower to libm `trunc`/`round` for `real(4)` and `real(8)` arguments, elementally over a whole real array, and take an optional `KIND` selector: a foldable 4 or 8 fixes the result kind (the argument converts to that kind first, matching gfortran), an unfoldable selector keeps the wide `real(8)` result, and any other kind is rejected; a nonreal argument is rejected. **Numeric-model inquiry:** scalar `tiny(x)`, `huge(x)`, and `epsilon(x)` of a `real` argument (a literal, an array constructor, or a variable of kind 4 or 8) lower to the constant real value for the argument's kind and are usable in real expressions, conditions, and `print`; `huge` of an `integer` argument keeps folding to its integer bound. **Bit:** `iand`, `ior`, `ieor`, `not`, `ishft`, `ishftc`, `ibits`, `ibset`, `ibclr`, `btest`, `bit_size` on default `integer` values. **Bit reinterpret:** scalar `transfer(source, mold)` between `integer(4)`/`real(4)` and between `integer(8)`/`real(8)`, reinterpreting `source`'s bit pattern as `mold`'s type by storing through a typed stack slot and loading it back with the other type (the same memory-punning `EQUIVALENCE` already relies on); `source` may be an identifier, a declared or allocatable array element, or a literal, and same-kind `transfer` is the identity. A whole-array assignment `a = transfer(source, mold[, size])` applies the same reinterpretation elementwise: `source` is a scalar expression or a declared whole array, the source and result element kinds must share a byte size, `size` (when present) must be a non-negative compile-time constant equal to the result array's size, and the source must supply at least as many elements as the result. Any other source/mold kind pairing (including character or narrower integer kinds), a runtime-sized or assumed-shape source array, and a non-constant `size` stay unsupported. **Array:** `size`, `sum`, `product`, `maxval`, `minval`, `norm2` (real arrays only, scalar over a whole array or a rank-1 section, and `norm2(a, dim)` over a rank-2 real array into a rank-1 real target; | Pointers | Scalar integer, real, and logical `pointer` and `target` (#245 slice B3a). A `target` local lives in a stable memory slot. The two-argument form compares the compile-time address operand in `p`'s symbol against the named target; it folds to a constant with no emitted code. `procedure(...), pointer :: fp` (#245 B3d) allocates a `ptr` alloca slot; `fp => my_func` stores the function address into it; a call through `fp` loads the slot and dispatches via an indirect `LR_OP_CALL`. Returning the address of a local automatic target is rejected with `pointer result target does not outlive the function`. | Polymorphism | An unlimited-polymorphic `class(*)` dummy is supported: a scalar actual (integer, real, or logical) is boxed into a `{void* data; i64 type_id}` descriptor passed by reference. A rank-1 integer whole-array actual may also bind to `class(*), intent(in) :: values(:)` through the canonical array descriptor; `select type (items => values)` narrows the descriptor-backed view, including `size(items)` and element reads. This array slice intentionally supports only integer actuals for now; sections, allocatable arrays, and real/logical class-star arrays remain explicit refusals. `select type` on a `class(*)` selector (both `select type (v)` and `select type (a => v)`) dispatches on the runtime type id: each `type is (integer|real|logical)` arm runs when it matches with the associate name rebound to the concrete value, and `class default` runs when none match. A `class(t)` scalar dummy is passed as the canonical scalar class descriptor (`docs/RUNTIME_ABI.md`), which carries its declared type identity, its dynamic type identity, and borrowed ownership; the dynamic identity is preserved when the dummy is handed on to another `class(t)` dummy. An actual whose declared type is neither `t` nor an extension of `t` is rejected. `select type` on such a selector dispatches from that runtime identity: the identity is loaded once, `type is (u)` matches the exact type `u`, `class is (u)` matches `u` and every extension of it, and `class default` runs when nothing matches. Guards are evaluated in the order Fortran 2018 11.1.11.2 prescribes - every `type is` guard first, then the most specific `class is` - independently of the order they were written in, and inside an arm the associate name aliases the selector's storage with its declared identity narrowed to the guard's type. Two guards naming the same type, and a guard naming a type outside the selector's declared hierarchy, are rejected. A `class(t)` local (non-allocatable, non-pointer) still resolves statically, since its dynamic type is its declared type. `class(*)` locals, `class(*)` derived-type guards, dynamic dispatch on an allocatable polymorphic object, and assumed-rank `select rank` (see the `select rank` row) are unsupported. A `class` (polymorphic) entity at main-program or module scope that is neither allocatable nor a pointer is rejected ("must be dummy, allocatable or pointer"). An `elemental` procedure with a scalar `class(t)` dummy may also be called with a whole fixed-size derived array actual: the call is applied elementwise at the actual type's own element stride, so an extension of `t` passes its element base address per element. An actual whose declared type is neither `t` nor an extension of `t` is rejected with a diagnostic. |
| Derived types | An empty or behavioral-only type (no data components, e.g. a bare `type :: t; end type` or a type carrying only a `contains` type-bound-procedure block) registers with a single hidden i32 placeholder slot, so `type(t)`/`class(t)` declarations, type-bound dispatch, allocation, and extension resolve against it instead of failing to register. Simple program-scope derived type definitions with scalar integer, real (`real`, `real(real64)`), logical, `c_ptr`, and fixed-length character (`character(len=N)`) components, plus fixed-size rank-1 integer, real, and logical array components (`integer :: a(N)`, `real :: r(N)`, `logical :: f(N)`, N a literal or integer parameter). Each array element occupies one i32 slot, except a `real(real64)` element which spans two, so element addressing scales the index by the slot width. A character component occupies `ceil((N+1)/4)` i32 slots, with a NUL terminator in the spare byte. Scalar variables of those types are supported. Fixed-size arrays of derived-type instances (`type(t) :: arr(N)`) with element-component access (`arr(i)%comp`) are supported, including rank-2 (`type(t) :: g(2,4)`, `g(i,j)%comp`), which addresses column-major within the flat slot storage. A derived array is one symbol however the declaration is reached, so a derived-array dummy (`type(t), intent(inout) :: x(1:4)`) binds the caller's storage instead of colliding with the parameter. A whole derived array and a contiguous section of one (`g(1:2,3)`, `arr(2:3)`) pass by reference to an explicit-shape derived dummy, which views the caller's elements in place; a non-contiguous derived section (`g(2,1:4)`) still declines. An array whose elements carry allocatable components passes the same way (#406): the outer array is the caller's contiguous element block, and each element's component descriptor stays owned by the actual, so the dummy borrows it and reads `size(arr(i)%comp)` and `arr(i)%comp(j)` through the caller's heap data. A rank-1 or rank-2 assumed-shape derived dummy (`type(t) :: arr(:)`, `arr(:,:)`) binds the same storage and takes its shape from the whole-array actual at the call site; a shape that cannot be recovered there is rejected. `size()` of a derived array reports its element count, not its slot count. An actual whose declared type differs from that of a `type(t)` dummy is rejected, and writing an element component through an `intent(in)` derived dummy (`arr(i)%comp(j) = ...`) is a variable-definition-context diagnostic. A contained function may return a whole derived value (`q = make_point()`), passed via a hidden result-address argument. Component assignment, component reads, array-component element access (`x%a(i)`), whole-component assignment from an array constructor (`x%v = [1, 2, 3]`), scalar broadcast (`x%v = 7`), whole-component copy (`y%v = x%v`), reading the whole component into a conforming plain array (`a = x%v`), `print`, and `stop` are supported. Reading, writing, comparing (`==`/`/=`/`<`/...), concatenating, printing, and passing as an actual argument to a `character(len=*)` dummy a fixed-length character component (`x%name`) are supported, matching gfortran's blank-padded fixed-length semantics. A scalar nested derived component (`type(inner) :: c` inside an outer type) lays the inner type's slots inline and is accessed to any depth through its leaf scalar (`x%c%field`, `x%mid%inner%value`); the inner type may itself carry array components reached as a whole instance, but indexing an intrinsic array component through a nested base (`x%c%v(i)`) is not yet supported. A fixed-size array of derived components (`type(inner) :: arr(N)` inside an outer type, rank-1 or rank-2) lays each element's inner slots inline (spanning `N` inner instances); an element is selected by subscript and its fields reached through the chain (`x%arr(i)%field`), including deeply nested subscript chains (`obj%w(1)%z(2)%y(3)%leaf`) and an allocatable-array leaf reached through them (`allocate(obj%w(1)%z(2)%y(3)%x(n))`, `size(...)`). Component defaults and allocatable-descriptor nulling propagate to every element of the array, not just the first. A rank-1 allocatable array of a derived element type (`type(inner), allocatable :: c(:)`) lays the same inline 16-byte descriptor; `allocate(x%c(n))` `calloc`s `n` zero-initialised inner instances (so each element's own allocatable-component descriptors start unallocated), `x%c(i)%field` element-component access loads the component data pointer and steps in by whole inner instances before adding the field slot, and `allocated(x%c)`, `size(x%c)`, and `deallocate(x%c)` manage the descriptor. These stack through several heap indirections (`obj%z(i)%arr(j)%arr(k)`) since an inner element may itself hold an allocatable derived or intrinsic allocatable array component; `class(inner)` array components share this monomorphic path. Non-zero scalar component defaults on heap elements, whole-component assignment of a derived array, and allocatable derived array dummy arguments remain unsupported; pointer arrays of derived components and genuinely polymorphic `allocate(..., source=)` still decline. Default initialisation propagates through nested components: an inner type's own scalar component defaults materialise in an outer instance (`x%c%field` reads the inner default, not zero), and a nested component may carry a bare inner-type default-constructor initialiser (`type(inner) :: c = inner()`), which is equivalent to that default initialisation; an argument-bearing nested initialiser stays unsupported. A bare argumentless structure constructor (`v = t()`, or a `type(t) :: v = t()` initialiser) applies the type's default initialisation, including for a type with nested components that the argument-storing constructor path cannot build. A derived value passes to a `type(t)` dummy by reference (the address of its component storage). A module-defined derived type resolves inside that module's procedures: a `type(t)` dummy (`intent(in)`/`out`/`inout`), local, or whole-derived result uses the same component layout as a program-scope type. A non-overridable type-bound binding (`procedure :: m => impl`) is callable as `obj%m(args)`, lowered to a direct `impl(obj, args)` with the object as the first argument (default `pass`); a `pass(name)` binding routes the object to the named dummy's position instead. A single scalar `final` binding is modelled: the named procedure is called once with the value's storage address when an owned scalar value of the type reaches the end of its lifetime, that is when the procedure owning a local derived variable ends execution, and at `deallocate` of an owned allocatable scalar before the storage is released. A dummy argument borrows the caller's storage and is never finalised there, and a moved-from or already deallocated allocatable has no address left to finalise. Array finalisation, inheritance override dispatch, finalisation on abnormal termination, and a type declaring several `final` bindings (ambiguous for the scalar case) stay rejected. Single inheritance (`type, extends(parent) :: child`) is supported: the child lays the parent's components first then its own (parent-first layout), so an inherited parent component is reachable on a child instance (`child%parent_comp`), an inherited array component keeps its element count, and a parent type-bound procedure is callable on a child instance through the inherited static binding. The parent must be defined before the extending type, and a child that declares its own type-bound procedures (override/extension) is not yet supported. A whole-derived scalar assignment copies one instance into another of the same type slot-by-slot (`y = x`). A scalar structure constructor whose components are all scalar `integer`/`real`/`logical`/fixed-length character stores its positional arguments into the target's slots (`x = t(1, 2.5, .true.)`, `x = person_t("Ada", 7)`); a component omitted from the constructor keeps its compile-time default, and inherited components construct in parent-then-child order. The same constructor also initialises a scalar derived variable at its declaration (`type(t) :: v = t(1, 2.5)`), materialised as an initialisation store into the fresh instance; a program-scope scalar derived `parameter` with a constructor initialiser (`type(t), parameter :: p = t(2, 3)`) lowers through the same initialised-instance path. A scalar `integer`, default-`real` (f32), `real(real64)`, `logical`, fixed-length `character(len=N)`, or `type(c_ptr)` (`c_null_ptr` only) component default initialiser folds into the type's compile-time slot bytes and materialises when an instance is default-initialised, and when a structure constructor omits that component. A non-constant or type-incompatible default is rejected with a component-initializer diagnostic. A scalar allocatable component of intrinsic numeric or logical type (`integer, allocatable :: v`, also `real`/`real(real64)`/`logical`) lays an inline 8-byte data pointer in the instance (two i32 slots), null on default initialisation; `allocate(x%v)` mallocs a typed slot and stores the pointer, `x%v` reads and writes dereference it, `allocated(x%v)` (in a condition) tests the pointer, and `deallocate(x%v)` frees the slot and restores the null pointer. A rank-1 allocatable array component of intrinsic numeric or logical type (`integer, allocatable :: v(:)`, also `real`/`real(real64)`/`logical`) lays an inline 16-byte descriptor (an 8-byte data pointer at byte 0 plus an i64 element extent at byte 8, four i32 slots), null on default initialisation; `allocate(x%v(n))` with a runtime extent mallocs `n * elem_size` bytes and records the pointer and extent, `x%v(i)` element read/write offsets through the data pointer (lower bound 1), `allocated(x%v)` tests the pointer, `size(x%v)` reads the stored extent, and `deallocate(x%v)` frees the data and nulls the descriptor. Whole-component assignment reallocates the component to the right-hand side extent and stores each element: from an explicit array constructor (`x%v = [1, 2, 3]`) or from a whole plain-array or allocatable variable of compile-time extent (`x%v = test`); any current data is freed first, so a re-assignment resizes. `sum(x%v)` over a whole integer component reduces through a runtime loop over the stored extent, and `all`/`any` of an elementwise integer comparison between a whole component and a conforming array (`all(x%v == a)`, `any(x%v /= a)`) reduces over the array's static extent. A scalar-broadcast right-hand side, a whole-component read into a plain array, a real/logical `sum`, other reductions, and passing the component as an actual argument stay unsupported and decline gracefully. A constructor with a nested-derived, array, or `c_ptr` component argument, a keyword (`name=value`) argument, or whose type name is overloaded by a generic interface or contained function, falls back to the unsupported diagnostic rather than mis-constructing. A scalar allocatable deferred-length character component (`character(len=:), allocatable :: s`) lays the canonical 16-byte character descriptor inline (data pointer at byte 0, i64 length at byte 8, four i32 slots), null and zero-length on default initialisation; `x%s = expr` allocates `len+1` bytes, deep-copies the right-hand side bytes, NUL-terminates the spare byte, and frees the previously owned buffer exactly once, so re-assignment resizes; reading, `len(x%s)`, comparison, concatenation, and `print` follow the stored length; a whole-derived copy (`y = x`) re-owns the destination's buffer so the two values stay independent, releasing the destination's own data first; `allocated(x%s)` tests the data pointer and `deallocate(x%s)` frees it and clears both descriptor halves, so a repeated `deallocate` is a no-op rather than a double free. Type parameters, pointer components, character array components, and array-component default initialisers are unsupported. |
| Class-star rank-2 array boundary | This row supersedes the older rank-1-only wording in the Polymorphism row: a rank-2 whole `integer` or `real(8)` actual binds to `class(*), intent(in) :: values(:,:)` through the canonical 200-byte descriptor. `select type (items => values)` narrows the same borrowed view; `size(items,1)`, `size(items,2)`, total `size(items)`, and column-major element reads use descriptor extents and strides. Rank-3-and-higher arrays, default/single-precision real, logical and other unsupported kinds, sections, allocatable arrays, pointers/targets, and global ownership are exact refusals. The independent gfortran differential and refusal oracle is `test_session_class_star_rank2_assumed_shape_compiler`. |
| CLI | `-o <file>`, `-c`, `-I <dir>` (the include directories are searched for `.fmod` module artefacts on `use`), `--backend default\|isel\|copy-patch\|llvm` (selects the liric session codegen backend; `default` and the two native backends are supported, `llvm` requires a liric built with the LLVM backend), `--json` (emits failed compiler diagnostics as JSON on stderr), and positional `.o` link inputs. The source file may appear at any positional slot. Text diagnostics use `file:line:column: error:` on stderr. Two-file separate compilation works: `ffc -c m.f90 -o m.o` then `ffc main.f90 m.o -o main`; the linked object's directory is also searched for its `.fmod`. Because module exports are compile-time constants and layout-only types, they fold into the program and the emitted executable is self-contained. |
| Module procedures | A module that `contains` procedures compiles either accompanied by a program unit or as a bare module-only unit (lowered to a no-main object): each module procedure is emitted under the mangled symbol `__<module>_MOD_<name>` (gfortran convention), so two modules may define a procedure of the same name without colliding, and calls through `use` resolve to the mangled symbol. A self- or sibling-call inside a bare module procedure resolves, so a recursive module function lowers. Integer, real, and logical dummy and result types are supported; a `logical`-valued module function called from a program in the same file resolves and prints as `T`/`F`. An `integer(8)` result returns through the i64 ABI (a value wider than 32 bits round trips), and an `integer(8)` scalar dummy is passed by reference at its native width; a call site whose result is bound to an `integer(8)` variable resolves through the i64 call path. Character dummy types use the same descriptor ABI as contained procedures. A deferred-length (`character(len=:)`) or runtime-length (`character(len=len(arg))`) character result returns through the deferred descriptor ABI and is callable and printable from a program in the same file; the deferred-character call site resolves the module-mangled symbol. A fixed compile-time-length character result (`character(len=N)`) stays unsupported (the descriptor return does not pad short assignments). A module procedure that itself `contains` an internal procedure is lowered: the internal procedures are emitted as flat functions under their plain Fortran names and calls inside the containing procedure resolve to them, the same flat-emission model used for program-contained procedures (no host association of the containing procedure's local variables). Across separate compilation a module subroutine, or an integer function, whose dummy arguments are all supported by-reference scalars (integer, real, or logical) is recorded in the `.fmod` with its per-argument kinds; a program that `use`s the module resolves the call to the mangled symbol, passes the arguments by reference with each actual materialised at the recorded kind, and links against the module object. Each separately compiled object namespaces its per-unit `.ffc.*` string, format, and character content globals by a hash of its output path, so linking a module object beside the program (or beside sibling module objects) no longer merges colliding globals and every unit keeps its own literals (#284). A named generic interface whose specifics are all such exportable procedures is recorded in the `.fmod` (its generic name and the specific names it resolves to); a program that `use`s the generic name (even through an `only:` list that names just the generic) resolves each call to the specific matching the actual's first-argument kind and links to it. A module that exports only contained procedures (no declaration part) still writes a `.fmod` so a using unit resolves it. |
| Procedure-only units | A source holding only top-level (external) procedures compiles with `-c` to an object that defines no `main`, so it links beside a separately compiled driver; every procedure of the unit is emitted under its plain external symbol, including one defined after the procedure that calls it. A driver declares such a procedure through a host-level `interface` block: the signature types the call, the arguments lower by reference, and the symbol resolves at link time instead of being rejected as a missing body (an interface inside a procedure's specification part names a dummy procedure, and needs its body in the unit, only when the interfaced name also appears in that procedure's dummy-argument list; any other name it declares is external and links the same way). Requesting an executable from a procedure-only source is rejected with `no main program unit` rather than emitting a do-nothing `main`; a module-only source keeps its established no-main object and no-op executable. |
| Submodules | A single source file holding `module m` (declaring module procedures through interface bodies), one or more `submodule (m) s` units that implement them, and a program that calls through `use m` compiles. Each submodule extends its parent module's scope; its procedures are emitted under the parent's mangled symbol `__<m>_MOD_<name>`, so a call site resolves to the interface the parent declared regardless of which submodule supplies the body. Both the restated form (`module function f(x) result(y)` with its signature and declarations repeated in the submodule) and the separate form (`module procedure f` with the body only) are supported: the separate form inherits the dummy declarations, result variable, and function-versus-subroutine kind from the parent interface. A named generic interface in the parent module may name its specific through a module-procedure interface body (`interface gen; module subroutine impl(...); end interface`) rather than a `module procedure` statement; a call through the generic name resolves to that specific and links to the submodule body implementing it. A submodule whose parent module is absent from the compilation set is rejected with `submodule parent module not found`. Separate-file submodules (parent module in another `.f90`/`.fmod`) and nested submodule chains (`submodule (m:s) s2`) are not yet supported. |
| Modules | A module defining named constants, derived-type definitions, module-level scalar variables, and procedures compiles. Constants fold at use sites; types are layout-only. Module integer, real, and logical scalar variables are emitted as zero-initialised globals named `__<module>_MOD_<var>` (gfortran convention) and persist across calls; the `.fmod` artefact records each variable's kind so cross-file separate compilation loads and stores it at the right type. A fixed-size rank-1 module array variable of the same element kinds is emitted as one `[extent x elem]` global under the same mangled name; its extent may be a literal or a compile-time named-constant expression (`dimension(m)` with `integer, parameter :: m`), and a plain array-constructor initialiser (`integer :: a(3) = [1, 2, 3]`) folds into the global's static bytes. Host association inside module procedures and `use` (including `use, only:`) bind the shared global, so element access, whole-array assignment/reduction, and `size`/bounds inquiries all read that one storage. A rank-1/rank-2 module-scope `allocatable` array of those element kinds is emitted instead as a zero-initialised 40-byte descriptor global (data pointer plus bounds) under the same mangled name, so it starts unallocated and `allocate` (including the multi-object `allocate(a(n), b(m))` form, each target with its own extents), `deallocate`, `size`, and element access from module procedures and using units all share that one descriptor. Pointer/character/derived-element and rank > 2 module arrays stay a clean diagnostic rather than compiling. `ffc -c` on such a source writes a sibling `<modulename>.fmod` describing the exports (see `docs/RUNTIME_ABI.md` module artefact format); a source that defines several modules and no program compiles with `-c` to a single object with a `.fmod` per module beside it. `use <module>` resolves against an in-unit module or, failing that, a `<module>.fmod` found on the `-I` search path or the current directory. An intrinsic module (`iso_c_binding`, `iso_fortran_env`, ...) is recognised without a `.fmod`; any other unresolved module is a diagnostic. `use, only:` names and rename targets are checked against the in-unit or `.fmod` export records; a rename such as `local => remote` binds the local spelling while preserving the remote storage/linkage name. Module accessibility is honored: a bare `private`/`public` sets the default, `private`/`public :: name` overrides per name, and the attribute form (`integer, private, parameter`) marks a single declaration; a private symbol is not exported through `use`. A module-scope scalar variable of a registered derived type is emitted as a flat `[slots x i32]` global whose static bytes carry the type's compile-time component defaults (zero where a component has none); a using unit reads and writes its components through that global, including under a `use ..., alias => var` rename. An explicit structure-constructor initialiser (`type(t) :: v = t(2, 3)`) folds its compile-time integer arguments into the global's static slots, overriding the component defaults; an argument that is not a constant integer for an integer component keeps the initialiser unsupported. A scalar derived `parameter` initialised by such a constructor (`type(t), parameter :: p = t(2, 3)`) exports through the same slot global and binds as a derived reference in using units (honouring `use, only:`), rather than through the integer-only named-constant path. |
| Interfaces | An `interface` block declaring `bind(c)` integer functions or `void` subroutines is parsed and registered (Fortran name, C name, argument and result kinds). Calls lower to a direct call on the C symbol with by-value arguments; an integer actual is passed as `i32`, and a `c_null_ptr` actual is passed as a null pointer (8 bytes). A plain (non-`bind(c)`) explicit interface declaring the signature of an external or module procedure is registered so the call type-checks and lowers its arguments by reference. When the real definition of that same procedure is present in the file (a top-level external function or module procedure of scalar integer, real, or logical result), the interface signature reconciles with the definition instead of colliding as a duplicate, and the call resolves to the real symbol for every scalar result kind. Operator interfaces are handled through the operator-overload table; `bind(c)` interfaces with a non-integer result are rejected. A contained procedure declared `bind(c, name="...")` is emitted under that unmangled C symbol (so it links from other languages), and internal calls resolve to the same symbol. A named generic interface whose two specific procedures have indistinguishable dummy signatures (equal argument count with every position a known-kind scalar of identical type and kind) is rejected with an `ambiguous interfaces` diagnostic (F2018 C1514); a pair that differs in any position's type, kind, or array rank, or any position whose type/kind cannot be resolved statically, is left to normal lowering so a valid generic is never rejected. A `procedure(iface) :: p` declaration statement names a procedure with the referenced explicit interface rather than introducing storage, both at module level and inside a generic `interface` block, so a `procedure p` specific inside a named generic resolves to it and a direct call `p(...)` links to the external definition. A referenced interface name that is missing or incompatible is left to the frontend; ffc does not diagnose it. When an explicit-interface body and the real definition of a function share a name, they are reconciled onto the body-bearing definition only if their result signatures agree; a mismatch in result rank, base type, or `pointer` attribute is a genuine error and is rejected ("rank/type/POINTER attribute mismatch in function result between interface and definition"). |
| `common` / `block data` | Named and blank COMMON blocks with scalar `integer(4)`/`real(4)`/`real(8)`/`logical`/`complex(4)`/`complex(8)` members, plus 1D arrays of the numeric/logical kinds. Each block member is one LIRIC global keyed by block name and position (not spelling), so a program and a subroutine or `block data` unit sharing a block name alias the same storage even when their member names differ (F2018 8.10.3); the `common` statement may appear before or after its member's own type declaration. A `block data` unit's `data` statement values, including a whole-array form with no subscript (`data arr /v1, v2, v3/`, one value per element in declaration order), fold into the shared storage's static initialiser. Character members, EQUIVALENCE-linked members, and cross-unit layouts that split the same block offset differently (a scalar in one unit aliasing the interior of another unit's array, or otherwise disagreeing byte-for-byte) stay unsupported; the latter is not diagnosed and can miscompile (#1578). |

| Runtime reductions | Rank-1 through rank-4 runtime automatic arrays or assumed-shape dummies support scalar `sum(a)`, `product(a)`, `maxval(a)`, and `minval(a)` over default integer, `real`, or `real(8)` elements. Static type-bound overrides are supported for a statically declared
`type(child_t)` receiver in `type, extends(parent_t) :: child_t`: a local

lowering with a diagnostic. Silent partial lowering is a bug.

package-level orchestration contracts.

## Feature admission rule

A feature becomes supported only after all of these are true:

1. The FortFront API surface used by `ffc` is public and documented.
2. Any new runtime ABI is documented in `docs/RUNTIME_ABI.md`.
3. The direct LIRIC session lowerer implements the feature.
4. Behavioural tests cover success behaviour and relevant diagnostics.
5. The support contract, README, and development plan are updated in the same
   change.
